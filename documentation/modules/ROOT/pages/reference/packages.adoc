= Packages
:description: Which packages are built for which distribution, what they depend on, and every file they install.

Every `v*` tag builds packages for `x86_64` and `aarch64` and attaches them to a
https://github.com/itbh-at/wusel/releases/latest[GitHub Release]. To actually
install one, see xref:how-to/install-a-package.adoc[Install a package].

Wusel comes as two packages:

`wusel`:: the mount — the binary, the systemd user service, and the desktop
  integration the binary provides itself over D-Bus: notifications, the Files
  sidebar entry and the GNOME Shell search provider.
`wusel-nautilus`:: the GNOME Files (Nautilus) integration — per-file emblems and
  the *Wusel* context menu. It requires `wusel` of exactly the same version.

Integration with a file manager is always its own package, named
`wusel-<file manager>`, so a machine installs only the file-manager libraries
it actually uses.

== The repository

Wusel is published as a signed repository through the openSUSE Build Service, at
`https://download.opensuse.org/repositories/home:/cdhermann:/wusel/`. Adding it
is the normal way to install; see
xref:how-to/install-a-package.adoc[Install a package].

[cols="1,1,2",options="header"]
|===
| Distribution | Repository | Architectures

| Fedora 44
| `Fedora_44`
| `x86_64`, `aarch64`

| openSUSE Tumbleweed
| `openSUSE_Tumbleweed`
| `x86_64`, `aarch64`

| Debian 13 (trixie)
| `Debian_13`
| `amd64`, `arm64`

| Ubuntu 26.04
| `xUbuntu_26.04`
| `amd64`, `arm64`
|===

The architectures are spelled the way each ecosystem spells them: an RPM
repository says `x86_64` and `aarch64`, a Debian one says `amd64` and `arm64`
for the same two machines.

The RPM repositories carry `gpgcheck=1` and a signing key at
`<repository>/repodata/repomd.xml.key`; the Debian ones a `Release.key`. Your
package manager verifies every package against it, and updates arrive with the
rest of the system.

Arch is not in the build service. The `PKGBUILD` under `packaging/aur/` builds
on your machine, from the release tarball of the version in its `pkgver` —
currently `0.2.2`, behind the other packages — not from the checkout it sits in.
The AUR itself is a xref:project/roadmap.adoc[roadmap] item.

== Single files, per release

Every `v*` tag also attaches both packages, per format and architecture, to its
https://github.com/itbh-at/wusel/releases/latest[GitHub Release]. These exist
for machines that cannot add a repository, and for distributions the build
service does not target.

[cols="2,2,2",options="header"]
|===
| File | Format | Built for

| `wusel-<version>-1.fc44.<arch>.rpm`,
  `wusel-nautilus-<version>-1.fc44.<arch>.rpm`
| RPM
| Fedora 44. The `fc44` is not decoration — the package is linked against that
  release's libraries.

| `wusel_<version>_<arch>_debian13.deb`,
  `wusel-nautilus_<version>_<arch>_debian13.deb`
| Debian package
| Debian 13 (trixie), and Ubuntu releases close enough to it. A `.deb` filename
  carries no distribution of its own, which is why the target is spelled into
  it. On an older Ubuntu — 24.04 LTS among them — expect it not to run.
|===

These are *unsigned*, and nothing updates them for you. Prefer the repository
wherever you can use it. If neither fits, build from source:
xref:how-to/install-from-source.adoc[Install from source].

== Dependencies

The mount needs no desktop. `wusel` states one dependency outright:

`fuse3`:: for the setuid `fusermount3` helper that an unprivileged mount needs.

The binary links only libc, libm and libgcc_s. Notifications, the sidebar entry
and the search provider are the `wusel` binary speaking D-Bus, which it does
without any library — the Shell activates the search provider on demand. So
`wusel` brings `fuse3` and nothing else: about four packages on a minimal
Fedora or Debian.

`wusel-nautilus` requires `wusel` of the same version and the libraries the
extension links against — the Nautilus extension library and GLib — resolved
automatically as soname dependencies. It brings only what Nautilus itself uses:
two more packages on Fedora, nine more on a minimal Debian, none of them GTK.
The extension is compiled against GTK but does not link it; the few clipboard
calls it makes resolve inside Nautilus, which has GTK loaded.

`wusel` *suggests* `wusel-nautilus` and `gnome-shell` — not required and not
recommended (on Arch, optional dependencies). Neither `dnf` nor `apt` installs
a suggestion by default, so a server or a KDE machine gets the mount and no
desktop stack. What such a machine loses is the emblems and the context menu;
the mount itself is unaffected.

The RPM subpackage also declares `Supplements: (wusel and nautilus)`: where
Nautilus is installed, `dnf` and `zypper` install `wusel-nautilus` along with
`wusel` on their own. Debian and Ubuntu have no such mechanism, so there
`wusel-nautilus` is installed by name.

NOTE: Before 0.2.2 the GNOME pieces were `Recommends`, which both package
managers *do* install by default.

== What the packages install

=== `wusel`

[cols="2,3",options="header"]
|===
| Path | What it is

| `/usr/bin/wusel`
| The binary — daemon and CLI in one.

| `/usr/lib/systemd/user/wusel@.service`
| The systemd *user* service template. One instance per account:
  `wusel@default`, `wusel@work`.

| `/usr/share/icons/hicolor/scalable/apps/at.itbh.Wusel.svg`
| The full-colour application icon — the app-grid / launcher entry and the search
  results.

| `/usr/share/icons/hicolor/symbolic/apps/at.itbh.Wusel-symbolic.svg`
| The monochrome variant GTK re-tints to the theme foreground. The file-manager
  sidebar entry uses it, so it stays legible in Dark Mode.

| `/usr/share/applications/at.itbh.Wusel.desktop`
| The launcher entry the search provider resolves its identity from.

| `/usr/share/dbus-1/services/at.itbh.Wusel.SearchProvider.service`
| D-Bus activation for the search provider — this is what lets GNOME Shell start
  it on demand, with nothing running in the background.

| `/usr/share/gnome-shell/search-providers/wusel-search-provider.desktop`
| The search provider's registration with GNOME Shell.

| `/usr/share/applications/org.freedesktop.CloudProviders.wusel.default.desktop`
| The Files sidebar registration for the *default* account. Named accounts
  register their own with `wusel desktop install-provider`.

| `/usr/share/licenses/wusel/LICENSE`, `/usr/share/doc/wusel/README.md`
| Licence and README (RPM and Arch). The `.deb` ships
  `/usr/share/doc/wusel/copyright` and its changelog instead.
|===

=== `wusel-nautilus`

[cols="2,3",options="header"]
|===
| Path | What it is

| `/usr/lib*/nautilus/extensions-4/libwusel-nautilus.so` (on Debian and Ubuntu
  `/usr/lib/<triplet>/nautilus/extensions-4/`)
| The native Nautilus extension: per-file emblems and a *Wusel* context submenu —
  *Make Available Offline* / *Stop Keeping Offline*, *Update Now*, *Open in
  Nextcloud*, *Open Folder in Nextcloud*, *Copy Internal Link*. Tied to the Nautilus major version, so it is
  built against the target distribution's own Nautilus.

| `/usr/share/icons/hicolor/scalable/emblems/wusel-emblem-*.svg`
| The emblem icons the extension draws. See
  xref:reference/file-states.adoc[File states].

| `/usr/share/licenses/wusel-nautilus/LICENSE`
| Licence (Arch). The `.deb` ships `/usr/share/doc/wusel-nautilus/copyright`
  instead.
|===

Removing `wusel` — not upgrading it — also deletes the sidebar
registrations `wusel desktop install-provider` wrote for named accounts, which
the package never owned. All three formats do this.

Nothing is installed into a home directory. Everything Wusel writes per user is
created at run time; see
xref:reference/files-and-directories.adoc[Files and directories].
